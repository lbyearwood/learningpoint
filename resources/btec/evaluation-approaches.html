Different Ways to Approach Evaluation Tasks in BTEC IT

General support material for writing stronger evaluation responses across BTEC IT assignments.

Back to BTEC IT

Introduction

Evaluation tasks are common in BTEC IT, but many students find them difficult because they require more than description. You are not just explaining what something is or what you have done. You are making a reasoned judgement about how effective, suitable or successful something is.

Evaluation usually includes analysis. This means you need to break something down and explain its impact. For example, you may need to explain how a design principle affects the user experience, how a technology affects a business, or how a software feature affects the final product.

What a good evaluation should include

A good evaluation will usually use more than one approach. You should not rely on only one method, such as listing strengths and weaknesses. Stronger evaluations often combine several approaches, such as comparing options, making a judgement, considering pros and cons, using evidence, explaining impact and suggesting improvements.

A good evaluation should usually include:

  • A clear judgement
  • Reasons for that judgement
  • Evidence or examples
  • Analysis of the impact
  • Strengths and limitations
  • Consideration of the client, target audience or end user
  • Comparison where useful
  • Possible improvements or alternatives
  • An overall conclusion

For example, if you are evaluating a website, you could compare it against the original requirements, judge its usability and accessibility, analyse the impact on the target audience, use testing evidence, suggest improvements and then make an overall judgement.

What evaluation means

Evaluation is different from description and analysis. Description explains what something is, analysis explains how and why something has an effect, and evaluation makes a judgement about how good, useful, suitable or successful something is.

For example, writing “The website uses a consistent colour scheme” is description because it only states what the website includes. A stronger evaluation would explain whether the colour scheme is effective, how it affects the user, and whether there are any limitations.

A better response would be: “The website uses a consistent colour scheme, which helps the pages look connected and professional. This makes the site easier for the target audience to understand because each page feels part of the same product. However, the colour contrast is not strong enough on some buttons, which could make the site less accessible for users with visual difficulties. Overall, the design principle has been used effectively, but accessibility needs to be considered more carefully.”

This is evaluation because it makes a judgement, explains the impact and considers a limitation. It does not just say what was included.

Why evaluation is difficult

Evaluation is difficult because many students stay at the description stage. They explain what something is, but they do not judge how effective it is.

A weak response might say: “I used a navigation bar on my website.”

This is not enough because it does not explain the impact.

A stronger response would say: “I used a navigation bar on my website so users could move between pages quickly. This is effective because it reduces confusion and makes the website easier to use. However, the navigation bar would be more useful if the current page was highlighted, as this would help users understand where they are.”

Evaluation is also difficult because there is rarely one perfect answer. You need to weigh up different points. Something may be useful in one way, but limited in another way. That is why strong evaluation often uses words such as:

  • “because”
  • “therefore”
  • “however”
  • “although”
  • “as a result”
  • “this means that”
  • “overall”

Different users you may need to consider

When evaluating, the word “user” can mean different people depending on the task. A strong evaluation considers the correct user group.

Client

The client is the person or organisation that asked for the product. They care about whether the solution meets the brief, supports their goals and solves the original problem.

For example, if you create a website for a local gym, the client may be the gym owner.

Target audience

The target audience is the group of people the product is designed for. They care about whether the product suits their age, ability, interests, needs and expectations.

For example, the target audience for the gym website may be adults aged 18 to 40 who want fitness classes.

End user

The end user is the person who actually uses the product. They care about whether it is easy to use, reliable, clear, accessible and useful.

For example, the end user may be someone browsing the gym website to find prices, opening times or class information.

Choosing the right evaluation approach

There is not one single way to evaluate. The best approach depends on the task.

For example:

  • If you are comparing two technologies, a comparison approach is useful
  • If you are judging a final product, a requirements-based approach is useful
  • If you are evaluating a business decision, a pros and cons or SWOT approach may be useful
  • If you are explaining why you made a choice, a justification approach is useful
  • If you are evaluating your own completed work, a reflective approach is useful
  • If you are advising a client, a recommendation or improvement-based approach is useful

The important point is that you choose approaches that help you make a clear judgement. In most strong evaluations, you will combine several approaches.

Approach 1: Making a judgement

What this approach is

Making a judgement is the most important evaluation approach. It means clearly deciding whether something is effective, suitable, successful or appropriate.

This is not the same as saying what something does. You must state how well it works and why.

When this approach is useful Questions to ask yourself
Use this when evaluating one specific thing, such as a design principle, software tool, technology, website feature, final product or user interface choice. It works well when the question asks whether something was effective, suitable or successful. Is it effective? Is it suitable? Is it successful? How well does it meet the purpose? Who benefits from it? What is the main limitation? What is my final judgement?

Best format

This is best written as an essay-style paragraph or a report paragraph. It does not usually need a table because the main skill is explaining your judgement clearly.

Example

The use of consistent navigation is effective because it helps users move around the website without confusion. The navigation bar appears in the same position on each page, which makes the website easier for the end user to learn and use. This improves usability because users do not have to search for links each time they visit a new page. However, the current page is not highlighted, so users may not always know where they are. Overall, the navigation is mostly successful, but it would be more effective if the active page was clearly shown.

Approach 2: Comparing options

What this approach is

A comparison approach means judging two or more options against each other. You explain which option is more suitable and why.

This is stronger than simply describing each option separately. You need to make links between them and decide which one is better for the scenario.

When this approach is useful Questions to ask yourself
Use this when there are different technologies, software tools, methods or design choices available. For example, server-side scripting compared with client-side scripting, cloud storage compared with local storage, a database compared with a spreadsheet, one software tool compared with another, different file formats, different security methods or different design layouts. What are the options? What does each option do well? What are the limitations of each option? Which option is better for this scenario? Which option is better for the client? Which option is better for the end user? Which option is more secure, efficient, accessible or reliable? What is my final decision?

Best format

This is often best done as a table followed by written paragraphs. The table helps you organise the comparison, but the written section is needed to explain your final judgement. For a shorter answer, this can be written as an essay-style paragraph.

Example

Server-side scripting is more suitable than client-side scripting for a login system because the username and password can be checked securely on the server. This protects sensitive data better than relying only on code running in the browser. Client-side scripting is still useful because it can check whether fields have been completed before the form is submitted, which improves the user experience. However, it should not be used by itself for authentication because browser-based code can be viewed or manipulated. Overall, server-side scripting is the better choice for secure login processing, while client-side scripting is better as a supporting feature for usability.

Approach 3: Pros and cons

What this approach is

A pros and cons approach means identifying the benefits and drawbacks of something before making a final judgement.

This is one of the easiest ways to structure an evaluation because it forces you to consider both sides.

When this approach is useful Questions to ask yourself
Use this when evaluating a technology, software choice, design decision, security method, business decision, use of automation, use of cloud storage or final product. What are the main benefits? Who benefits from these? Why do these benefits matter? What are the drawbacks? Who is affected by these drawbacks? How serious are the drawbacks? Do the benefits outweigh the drawbacks? What is my overall judgement?

Best format

This is often best done as a table for planning, followed by an essay or report paragraph. The table helps you list the positives and negatives, but the paragraph is needed to explain whether the advantages outweigh the disadvantages.

Example

Cloud storage is useful because it allows staff to access files from different locations and share documents more easily. This can improve collaboration and make the business more flexible. However, it depends on a reliable internet connection, so staff may not be able to access files if the connection fails. It also creates security risks if permissions are not managed correctly. Overall, the benefits outweigh the drawbacks for a business with staff working in different locations, but only if strong access controls and backup procedures are used.

Approach 4: SWOT analysis

What this approach is

SWOT stands for strengths, weaknesses, opportunities and threats. This approach helps you evaluate something from a wider business or project perspective.

Strengths and weaknesses are usually internal. They focus on the product, system, organisation or project itself. Opportunities and threats are usually external. They focus on what could happen in the future or what outside factors could affect success.

When this approach is useful Questions to ask yourself
Use this when evaluating a business IT decision, proposed technology, new system, impact of IT on an organisation, launch of a digital product, risks and benefits of a project, or whether a solution is suitable for a client. What are the strengths of this solution? What weaknesses could reduce its success? What opportunities could it create for the client or business? What threats or risks could affect it? Which factor is most important? Overall, is this a suitable decision?

Best format

This is best done as a SWOT table followed by a written judgement. The table is useful for organising ideas, but the written judgement is essential because it explains what the SWOT actually means.

Example

If a small business moves to an online booking system, a strength is that customers can book appointments more quickly. This could reduce the number of phone calls staff need to answer. A weakness is that staff may need training to manage the system properly. An opportunity is that the business could attract more customers online and collect useful booking data. A threat is that poor cybersecurity could damage customer trust if personal data is not protected. Overall, the online booking system is suitable if the business manages training, security and setup costs carefully.

Evaluation Approach 5: Justifying a choice

What this approach is

Justification means explaining why a choice was made and why it was appropriate.

This is slightly different from a general evaluation. You are defending a decision using reasons and evidence.

When this approach is useful Questions to ask yourself
Use this when explaining why you chose a specific software tool, used a particular design principle, selected a technology, used a particular file format, chose a database instead of a spreadsheet, or chose one solution over another. What choice did I make? Why did I make this choice? How does it meet the requirements? How does it help the client, target audience or end user? What alternative could I have used? Why was my choice better for this situation? What limitation does my choice still have?

Best format

This is best written as a report section or essay-style paragraph. It works well with a clear heading such as “Justification of software choice” or “Justification of design decisions”.

Example

I chose Microsoft Access instead of Excel because the client needed to store linked customer, order and product data. Access is more suitable because it allows related tables, primary keys and foreign keys to be used, which reduces duplication and improves data accuracy. Excel could have been used for a simple list of orders, but it would be less suitable for managing relationships between customers and orders. Overall, Access was the better choice because the client needed a structured database rather than a basic spreadsheet.

Approach 6: Evaluating against requirements

What this approach is

This approach judges how well something meets the original requirements, brief or success criteria.

This is one of the strongest approaches for BTEC IT coursework because many assignments are based on a client scenario.

When this approach is useful Questions to ask yourself
Use this when evaluating your final product, a website, database, spreadsheet, animation, app, digital product or system created for a client brief. What was the original requirement? Has it been fully met, partly met or not met? What evidence proves this? How does this affect the client? How does this affect the target audience or end user? Which requirements were most important? Overall, how successful is the product?

Best format

This is best done as a table followed by a written conclusion. The table helps you check each requirement clearly, but the written section is needed to explain the overall success of the product.

Example

The product mostly meets the client’s requirements because the website includes product information, contact details and clear navigation. These features help the end user find key information quickly. However, the mobile layout is only partly successful because some images take too much space on smaller screens. This affects the target audience because many users may access the site from a phone. Overall, the website is fit for purpose, but the mobile design is the weakest area.

Approach 7: Impact analysis

What this approach is

Impact analysis means focusing on the effect something has. You are not just saying whether something is good or bad. You are explaining what difference it makes.

This approach is useful when the task asks about the impact of a design choice, technology, software feature or IT system.

When this approach is useful Questions to ask yourself
Use this when evaluating the impact on the client, target audience, end user, business, staff, customers, data security, efficiency, accessibility, user experience, cost or performance. What impact does this have? Who is affected? Is the impact positive or negative? Is the impact short-term or long-term? How serious is the impact? What evidence shows this impact? Does the impact make the solution more or less suitable?

Best format

This is best written as a report because impact can be split into different sections. For example, you may have one section on impact on the client, one section on impact on the target audience and one section on impact on security.

Example

Using validation rules in the database has a positive impact on data accuracy because it reduces the chance of users entering invalid data. This benefits the client because the business can rely on the information stored in the database when contacting customers or processing orders. However, validation does not prevent every possible mistake because users could still enter incorrect but realistic data. Overall, validation improves accuracy, but it should be supported by verification checks and clear input instructions.

Approach 8: Cause and effect

What this approach is

Cause and effect evaluation explains how one decision leads to a particular result. This approach helps you move beyond description because it focuses on consequences.

When this approach is useful Questions to ask yourself
Use this when evaluating design principles, user interface decisions, security choices, software features, database validation, automation, performance issues or accessibility choices. What decision was made? What does it cause? What effect does this have on the user, client or system? Is the effect positive or negative? Is there a knock-on effect? Does this make the solution more successful?

Best format

This is best written as an essay-style paragraph. It is useful inside a longer report because it helps you explain impact clearly.

Example

Because the website uses clear headings and subheadings, users can scan the page more quickly and find the information they need. This affects the end user positively because they do not have to read every section in detail before finding relevant content. However, some pages contain too much text, which reduces the impact of the headings. Therefore, the heading structure is useful, but the content should also be concise.

Approach 9: Reflective evaluation

What this approach is

Reflective evaluation means looking back at your own work and judging what went well, what did not go well and what you would change. This is not just a diary of what happened. It must still include judgement and impact.

When this approach is useful Questions to ask yourself
Use this when evaluating your own project, final product, development process, testing process, how you responded to feedback or how your design changed over time. What worked well in my product or process? What evidence shows this? What problems did I face? How did I respond to those problems? What changed because of feedback or testing? What would I do differently next time? What was the most important lesson from the process?

Best format

This is best written as a reflective report. It can be written in first person if the assignment allows it, but it must still sound professional and evidence-based.

Example

My final website was mostly successful because it met the main client requirements, including a home page, product information and a contact form. The strongest part was the navigation because users could move between pages easily during testing. However, my development process was less effective when optimising images because some files were too large, which affected loading speed. If I completed the project again, I would compress images earlier in the process and test performance throughout development. Overall, the product was suitable, but the development process could have been more efficient.

Approach 10: Criteria-based evaluation

What this approach is

Criteria-based evaluation means judging something using clear categories. This makes your evaluation more organised and helps you avoid vague comments.

Possible criteria include:

  • Fitness for purpose
  • Usability
  • Accessibility
  • Security
  • Efficiency
  • Accuracy
  • Reliability
  • Maintainability
  • Performance
  • Visual design
  • Suitability for target audience
When this approach is useful Questions to ask yourself
Use this when evaluating websites, software, databases, spreadsheets, digital products, user interfaces or final solutions. Which criteria matter most for this task? How well does the product meet each criterion? What evidence supports my judgement? Which criterion is the strongest? Which criterion is the weakest? Overall, is the product successful?

Best format

This is best done as a table followed by written paragraphs. The table helps organise the criteria, but the written paragraphs are needed to explain which criteria matter most and why.

Example

The website is strongest in usability because the navigation is clear and consistent across all pages. This helps the end user find information quickly. However, accessibility is only partly successful because some images do not include alternative text. This could make the site harder to use for people who rely on screen readers. Overall, the website is usable, but it is not fully accessible.

Approach 11: Cost, benefit and risk

What this approach is

This approach evaluates whether something is worth doing by considering what it costs, what benefits it creates and what risks it introduces.

Cost does not always mean money. It can also mean time, training, effort or technical complexity.

When this approach is useful Questions to ask yourself
Use this when evaluating new software, new technology, business systems, cloud services, cybersecurity methods, automation, hardware upgrades or system changes. What are the costs? What time or training is needed? What benefits does it create? What risks does it introduce? Are the benefits worth the costs? Can the risks be managed? Should the client use this option?

Best format

This is best written as a report section. A table can be useful if there are several costs, benefits and risks to organise first.

Example

Using a cloud-based customer management system would benefit the business because staff could access customer records from different locations. This may improve customer service and reduce delays. However, the client would need to pay subscription costs and train staff to use the system correctly. There is also a security risk if user permissions are not managed properly. Overall, the system is worth using if the business needs remote access and is prepared to manage the cost and security risks.

Approach 12: Short-term and long-term evaluation

What this approach is

This approach looks at the immediate impact and the future impact. It is useful because some IT decisions seem positive at first but create future issues, or they may be difficult at first but useful later.

When this approach is useful Questions to ask yourself
Use this when evaluating new technologies, business systems, software implementation, training, automation, cloud storage, security changes or hardware upgrades. What is the short-term impact? What is the long-term impact? Will it save time later? Will it require training now? Will it become more expensive over time? Will it still be suitable in the future? What problems could appear later?

Best format

This is best written as a report with clear paragraphs for short-term and long-term impact.

Example

In the short term, moving to cloud storage may be challenging because staff need training and files need to be transferred from the old system. This could temporarily reduce productivity. In the long term, it could improve efficiency because staff can access shared files from different locations and collaborate more easily. However, the business must monitor storage costs and user permissions over time. Overall, cloud storage is a suitable long-term solution if the client manages security and cost carefully.

Approach 13: Stakeholder-based evaluation

What this approach is

This approach evaluates the impact on different groups of people. In BTEC IT, this is very useful because “user” can mean different things.

A stakeholder could be:

  • The client
  • The target audience
  • The end user
  • Staff
  • Customers
  • Managers
  • Technical support staff
  • The business owner
When this approach is useful Questions to ask yourself
Use this when evaluating websites, business systems, databases, apps, digital products, new technologies or changes to IT systems. Who is affected? What does the client need? What does the target audience need? What does the end user need? Are there conflicts between different needs? Which stakeholder is most important in this scenario? Overall, is the solution suitable for the key stakeholders?

Best format

This is best done as a table followed by a report section. The table helps organise different stakeholders, but the written judgement explains which stakeholder matters most and whether their needs have been met.

Example

The website is suitable for the client because it presents the business clearly and allows customers to make contact through the form. This supports the client’s aim of gaining enquiries. It is also mostly suitable for the end user because the navigation is simple and the pages are easy to follow. However, the target audience may expect a more interactive experience, such as online booking or product filtering. Overall, the website meets the basic needs of the main stakeholders, but it could offer more functionality for users.

Approach 14: Evidence-based evaluation

What this approach is

Evidence-based evaluation uses test results, feedback, data or examples to support your judgement. This is stronger than just giving your opinion.

When this approach is useful Questions to ask yourself
Use this when evaluating testing outcomes, final products, user feedback, performance, usability, accessibility, accuracy or whether a product works as intended. What evidence do I have? What did testing show? What did users say? What errors were found? What was successful? What does the evidence prove? Does the evidence support my judgement?

Best format

This is best done as a report with evidence included. A table can be useful for organising test results or feedback, but you still need paragraphs explaining what the evidence proves.

Example

The testing evidence shows that the contact form works because it accepted valid data and rejected missing required fields. This means the form is functional and helps collect the information the client needs. However, user feedback showed that the error message was not specific enough, so users were unsure which field needed correcting. Overall, the form works technically, but the user experience is only partly successful.

Approach 15: Significance ranking

What this approach is

Significance ranking means judging which point matters most. This is useful for higher-quality evaluation because it shows that you can prioritise rather than just list strengths and weaknesses.

When this approach is useful Questions to ask yourself
Use this when evaluating several problems, several strengths, different design issues, different risks, different technologies, client requirements or improvements. Which issue matters most? Which issue has the biggest impact on the user? Which issue has the biggest impact on the client? Which issue affects security, accuracy or usability the most? Which issue should be fixed first? Why is this more important than the others?

Best format

This is best done as a ranked table followed by a paragraph explaining the ranking. The paragraph is important because it shows why one issue matters more than another.

Example

The most significant issue is the unclear error messages because this directly affects whether users can complete the form successfully. Large images are also a problem because they may slow down the website, but users can still complete the main task. The colour scheme is less important because it affects presentation more than functionality. Overall, improving error messages should be the priority because it has the greatest impact on usability.

Approach 16: “So what?” evaluation

What this approach is

The “so what?” approach helps turn description into analysis and evaluation. After each point, ask “so what?” until you explain why it matters.

When this approach is useful Questions to ask yourself
Use this when your writing sounds too descriptive. It is useful for almost any evaluation task. So what does this do? So what impact does it have? So what difference does it make to the user? So what difference does it make to the client? So what does this mean overall?

Best format

This is best used as a paragraph-writing technique. It does not need a table. It helps you improve the quality of your explanation inside an essay or report.

Example

The website uses a consistent layout, which makes the pages easier to understand. This means users can learn how to move around the site more quickly, improving usability. Overall, the consistent layout makes the website more suitable for the target audience because they can find information without confusion.

Approach 17: “However and overall” evaluation

What this approach is

This approach helps you create balance. Evaluation should not be one-sided. You should explain what is effective, then use “however” to explain a limitation, then use “overall” to make your final judgement.

When this approach is useful Questions to ask yourself
Use this when your answer only gives positives, only gives negatives, needs more balance, needs a quick structure, or evaluates one feature or design choice. What is good about this? Why is it good? However, what is the limitation? How serious is the limitation? Overall, is it still effective?

Best format

This is best written as a paragraph. It is particularly useful for shorter essay or report responses.

Example

The use of animation is effective because it makes the homepage more engaging and draws attention to important content. However, too much animation could distract users or slow down the page, especially on mobile devices. Overall, animation is suitable if it is used carefully and does not make the website harder to use.

Approach 18: Recommendation-based evaluation

What this approach is

This approach ends with a clear recommendation about what should happen next. It is useful when you are evaluating options and need to advise a client.

When this approach is useful Questions to ask yourself
Use this when evaluating which technology a client should use, which software is most suitable, what improvements should be made, whether a system should be adopted, whether a product is ready to use, or what option is best for the scenario. What should the client do? Which option is best? What should be changed first? What evidence supports this recommendation? What risks should be considered? Why is this recommendation suitable?

Best format

This is best written as a report because recommendations usually need explanation. It works especially well at the end of an evaluation.

Example

I would recommend that the client uses a relational database rather than a spreadsheet because the business needs to manage customers, orders and products as linked data. A spreadsheet would be easier to set up, but it would be less reliable as the amount of data increases. A relational database reduces duplication and improves accuracy because each type of data can be stored in a separate table and linked using keys. Overall, the database is the better recommendation because it is more suitable for long-term data management.

Approach 19: Suggesting improvements or choosing alternatives

What this approach is

This approach means identifying what could be changed, improved or replaced to make the product, system or decision more effective.

It is not enough to say “this could be improved”. You need to explain what the improvement is, why it is needed, who it would help and how it would make the solution better.

You can also suggest an alternative. This means explaining that another technology, software tool, design choice or method may be more suitable.

When this approach is useful Questions to ask yourself
Use this when evaluating a final product that has weaknesses, a website that could be more accessible or usable, a database that could be more accurate or efficient, a spreadsheet that could be more reliable, a technology choice that may not be the best option, software that had limitations, testing results that found errors, user feedback that suggested changes or a system that could be improved in the future. What is the main weakness or limitation? What specific improvement would solve this issue? Who would benefit from this improvement? How would it improve usability, accessibility, security, accuracy or efficiency? Is there an alternative technology or software tool that would work better? Why would the alternative be more suitable? Would the improvement create any new problems? Which improvement should be prioritised first?

Best format

This is best done as a table followed by written judgement if you have several improvements to suggest. If you are only suggesting one or two improvements, an essay or report paragraph is better.

Example improvement

One improvement would be to add clearer error messages to the contact form. At the moment, users may know that an error has happened, but they may not know which field needs correcting. This affects the end user because it could make the form frustrating to complete. A better solution would be to show a specific message, such as “Please enter a valid email address”, next to the relevant field. This would improve usability because users would understand exactly what to fix. Overall, this improvement should be a priority because it directly affects whether users can complete the form successfully.

Example alternative

An alternative to using a spreadsheet would be to use a relational database. The spreadsheet may be suitable for simple calculations and small amounts of data, but it becomes less effective when the business needs to manage linked data, such as customers, orders and products. A relational database would be more suitable because it can reduce duplication, improve accuracy and use relationships between tables. However, it would take longer to set up and staff may need training. Overall, the database would be the better long-term option if the client expects the amount of data to grow.

Choosing the best format

Essay format

Use an essay format when you need to explain one topic in depth.

This is best for:

  • Evaluating a technology
  • Evaluating a design principle
  • Comparing two options in detail
  • Making a detailed judgement
  • Justifying a choice

Essay writing allows you to develop your reasoning clearly. It is useful when the task needs detailed explanation rather than a list.

Report format

Use a report format when there are several areas to evaluate.

This is best for:

  • Evaluating a final product
  • Evaluating a business system
  • Evaluating a project
  • Evaluating stakeholder impact
  • Making recommendations
  • Analysing short-term and long-term impact

A report works well when you need headings and sections. For example, you could evaluate impact on the client, target audience and end user separately.

Table format

Use a table when you need to organise several points clearly.

This is best for:

  • Requirements checking
  • SWOT analysis
  • Pros and cons
  • Comparing options
  • Ranking issues
  • Criteria-based evaluation
  • Listing suggested improvements

A table is good for organising ideas, but it often needs a written judgement underneath. A table by itself may not explain your thinking in enough detail.

Combined format

The combined format is often the strongest format for BTEC IT. This means using a table to organise your evidence, followed by essay or report paragraphs to explain your judgement.

For example, you could use a table to compare a spreadsheet and a database, then write a paragraph explaining which is more suitable for the client and why.

Quick guide to choosing an approach

Task type Best approach Best format
Evaluate one design principle Making a judgement / cause and effect Essay-style paragraph
Evaluate server-side scripting Pros and cons / comparison / impact analysis Report paragraph
Compare database and spreadsheet Comparison Table plus written judgement
Evaluate a final product Requirements-based / criteria-based Table plus report
Evaluate business impact SWOT / cost, benefit and risk Report
Justify software choice Justification Essay paragraph or report section
Evaluate user feedback Evidence-based evaluation Table plus paragraph
Evaluate several problems Significance ranking Ranked table plus paragraph
Recommend a solution Recommendation-based evaluation Report
Suggest improvements or alternatives Improvement-based / alternative-based evaluation Table plus written judgement
Improve descriptive writing “So what?” approach Paragraph technique

Useful evaluation paragraph frame

Use this when you need a simple structure.

  • The chosen approach, feature or technology is effective because...
  • This is shown by...
  • This has a positive impact on...
  • However...
  • This limitation matters because...
  • Overall...

Example paragraph using the frame

Server-side scripting is effective because it allows secure processing to happen on the server rather than only in the user’s browser. This is shown by its use in login systems, where usernames and passwords can be checked against a database. This has a positive impact on security because sensitive data is not handled only by client-side code. However, server-side scripting can increase server workload if many users access the system at the same time. This limitation matters because poor performance could affect the end user experience. Overall, server-side scripting is suitable for secure web systems, especially where accounts, databases or personal data are involved.

Final checklist for students

Before submitting an evaluation, check that you have:

  • Chosen more than one evaluation approach where appropriate
  • Made a clear judgement
  • Explained why your judgement is reasonable
  • Included impact, not just description
  • Considered the client, target audience or end user
  • Used evidence or examples
  • Considered strengths and limitations
  • Compared options where useful
  • Suggested improvements or alternatives where useful
